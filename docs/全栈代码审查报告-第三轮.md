## 二、发现的问题（7 项，按严重度排序）

---

### 🔴 P0 — 安全漏洞

#### 问题 1：`PurchaseRequestController.list()` 缺少权限注解

**文件：** `PurchaseRequestController.java` 第 26-35 行

```java
@GetMapping
// ← 缺少 @PreAuthorize！任何登录用户都能查看所有采购申请
public ResponseEntity<ApiResponse<Page<PurchaseRequest>>> list(...)
```

**对比其他 Controller：**
```java
// OutboundRequestController — 有
@PreAuthorize("hasAuthority('warehouse:out')")

// WarehouseInventoryInController — 有
@PreAuthorize("hasAuthority('warehouse:in')")
```

**影响：** 普通护工/财务人员（无仓库权限）可通过直接请求 `/api/purchase-request` 浏览所有采购申请记录。虽然不能审批（审批接口有权限），但信息泄露也是安全事件。

**修复：** 加上 `@PreAuthorize("hasAuthority('warehouse:purchase')")`

### 🟡 P1 — 功能完整性 / API 设计

#### 问题 2：审批拒绝理由传递方式不统一

**文件：**
- `PurchaseRequestController` 行 50 — 用 `@RequestBody Map<String, String> body` 
- `OutboundRequestController` 行 47 — 用 `@RequestParam(required = false) String remark`

**问题：** 相同语义（审批 + 可选备注），用了两种完全不同的参数传递方式。Outbound 用 `@RequestParam` 意味着只能通过查询参数传拒绝原因——如果原因很长（超过 URL 长度限制 2048 字符），就会被截断。

**建议：** 统一为 `@RequestBody` 方式，或定义专用 DTO `ApproveRequest { String remark }`。

### 🟢 P2 — 代码整洁度

#### 问题 5：前端重复工具函数未抽取为 composable

以下函数在至少 **8 个 Vue 文件中**几乎逐字重复：

| 函数 | 出现页面 |
|------|---------|
| `formatMoney` / `formatAmount` | FundDashboard, ConsumptionTrend, FundReport, InventoryIn, InventoryOut, Stock, Budget... |
| `supplyCategoryLabel` | InventoryIn, InventoryOut, FundReport, Stock, Budget, OutboundRequest, PurchaseRequest... |
| `formatBankMoney` | Dashboard, Payment |

**建议：** 创建 `src/composables/useFormat.js`，返回这些纯函数：

```js
// src/composables/useFormat.js
export function useFormat() {
  function formatMoney(val) { /* ... */ }
  function supplyCategoryLabel(cat) { /* ... */ }
  return { formatMoney, supplyCategoryLabel }
}
```

每页只需 `const { formatMoney, supplyCategoryLabel } = useFormat()` 一行。预计减少 ~150 行重复代码。

---

#### 问题 6：`PaymentService` 仍有多处原始 JDBC 查询

**文件：** `PaymentService.java`

| 行号 | 查询方式 | 问题 |
|------|---------|------|
| 43-63 | `jdbcTemplate.query()` 手写 SQL | `listElderlyOptions` — 可用 MyBatis-Plus |
| 93-95 | `jdbcTemplate.queryForObject()` | `ensureElderlyExists` — 可用 ElderlyMapper.selectCount |
| 159-167 | `jdbcTemplate.queryForObject()` | 同上 |
| 193-203 | `jdbcTemplate.query()` callback | 复杂查询但可迁入 Mapper XML |
| 209-213 | `jdbcTemplate.queryForObject()` | 同上 |
| 229-239 | `jdbcTemplate.query()` | `loadElderlyNames` — 未使用 BatchNameLoader |

**影响：** 字段名硬编码在 SQL 字符串中，若 Entity 字段改名，这里不会报编译错误。

**建议：** 分两步——简单的 count/单表查询优先迁移 MyBatis-Plus；复杂的多表查询迁入 Mapper XML。`loadElderlyNames` 可直接改用 BatchNameLoader。

---

#### 问题 7：CORS 配置过于宽松

**文件：** `SecurityConfig.java` 第 75-76 行

```java
config.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS"));
config.setAllowedHeaders(Arrays.asList("*"));    // ← 允许任意请求头
```

**问题：** `allowedHeaders: ["*"]` 允许客户端发送任意自定义 Header，虽然配合 JWT 认证已经有一定防护，但 Recommended practice 是明确列出需要的 Header。

**建议：** 改为 `Arrays.asList("Authorization", "Content-Type", "X-Requested-With")`

## 五、最终建议
