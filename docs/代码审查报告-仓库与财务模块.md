## 二、发现的问题 — 按严重程度排列

### 🔴 P0 — 必须修复（数据准确性问题）

---

#### 问题 1：出库/入库的 `update()` 和 `delete()` 没有同步调整库存

**文件：**
- `InventoryInService.java` 第 158-173 行 (update)
- `InventoryInService.java` 第 176-181 行 (delete)
- `InventoryOutService.java` 第 133-149 行 (update)
- `InventoryOutService.java` 第 152-157 行 (delete)

**现状：**

```java
// InventoryInService.update() — 只改了入库记录，没有改库存！
public void update(Long id, InventoryInCreateRequest request) {
    InventoryIn in = inventoryInMapper.selectById(id);
    // ... 只 set 字段 ...
    inventoryInMapper.updateById(in);  // ← 库存表完全没动！
}

// InventoryInService.delete() — 同上
public void delete(Long id) {
    inventoryInMapper.deleteById(id);  // ← 库存没有扣回去！
}
```

**后果：** 编辑入库数量/删除入库后，`t_stock` 的 `quantity` 和 `total_value` 不会变化，导致库存永远对不上。

**修复建议：** `update()` 和 `delete()` 方法内必须先反查旧的 quantity/totalAmount，计算差额后更新对应 `supplyCategory` 的 stock 行。`delete()` 需要从 stock 中扣回被删除记录的贡献。

---

#### 问题 2：`StockService.list()` 不支持 `supplyCategory` 筛选，但前端在传

**文件：**
- `WarehouseStockController.java` 第 29 行：只接收 `warningOnly`，没有接收 `supplyCategory`
- `StockService.java` 第 18 行：`list(page, pageSize, warningOnly)` 没有 `supplyCategory` 参数
- `Stock.vue` 第 104 行：前端传了 `supplyCategory`，但后端无视

**后果：** 前端选了「集中供养库存」，列表不变——用户会困惑，看起来像 bug。

**修复：** `StockService.list()` 增加 `String supplyCategory` 参数，在 WHERE 子句中加上 `AND s.supply_category = ?`。

---

#### 问题 3：`FundUsageReportController` 的 `supplyCategory` 过滤逻辑自相矛盾

**文件：** `FundUsageReportController.java` 第 57-67 行

```java
if (supplyCategory != null && !supplyCategory.isBlank()) {
    wrapper.eq(InventoryOut::getSupplyCategory, supplyCategory);
}
wrapper.eq(InventoryOut::getSupplyCategory, "CENTRALIZED");  // ← 无论传了什么，最终都强制 CENTRALIZED
```

**后果：** API 参数 `supplyCategory` 形同虚设，永远只返回集中供养数据。如果未来需要查社会化资金使用明细，这个接口完全用不了。

**修复：** 删除第 67 行硬编码，第 57-59 行的条件筛选设置 `defaultValue = "CENTRALIZED"` 即可：

```java
@RequestParam(defaultValue = "CENTRALIZED") String supplyCategory
```

### 🟡 P1 — 应该修复（功能完整性问题）

---

#### 问题 4：`ExpenseRecord` 没有 `supplyCategory` 字段

**文件：** `ExpenseRecord.java`、`ExpenseRecordService.java`

**现状：** 入库同步生成支出时，`ExpenseRecord` 只记录了 `expenseType = "SUPPLIES"`，没有区分这笔支出是社会化采购还是集中供养采购。

**后果：** 财务管理模块在查询支出明细时，无法按供应类别筛选——比如民政局要来查「本月集中供养采购支出」，只能兜回仓库模块看。

**修复：** `t_expense_record` 增加 `supply_category VARCHAR(20)`，`InventoryInService.create()` 中同步写 `expense.setSupplyCategory(in.getSupplyCategory())`。

---

#### 问题 5：`WubaoUsageReport` 支出分类不区分集中供养采购

**文件：** `FinanceReportService.java` 第 98-155 行 (`wubaoUsage` 方法)

**现状：** 支出分类按 `BankTransaction.bizType`（如 SUPPLIES、SUBSIDY）分组，不关心这些 SUPPLIES 中有多少是集中供养的。

**后果：** 五保资金使用报告显示「总拨付 X 万元，总支出 Y 万元」，但无法说明 Y 中有多少比例用于集中供养物资采购。

**修复：** 在支出聚合时增加 `supplyCategory` 维度。可以从 `t_inventory_in` JOIN `t_expense_record` 取到带 category 的支出数据，然后在 `WubaoUsageReportVO.ExpenseBreakdown` 中增加分类。

---

**文件：** `InventoryOut.vue` 第 175-178 行

#### 问题 7：`StockService` 使用原始 JDBC，与项目其他 Service（MyBatis-Plus）风格不一致

**文件：** `StockService.java`

**现状：** 全项目都在用 MyBatis-Plus 的 `LambdaQueryWrapper` + `BaseMapper`，唯独 `StockService` 用的是 `JdbcTemplate.query()` + 手写 SQL + `RowCallbackHandler`。

**问题：** 不是 bug，但增加了维护负担——以后改字段名要同时改 SQL 字符串。而且 `StockMapper` 已经定义了 `selectByMaterialAndCategoryForUpdate`，说明 StockMapper 已经有 MyBatis 能力了。

**修复：** 改为用 `StockMapper` + `LambdaQueryWrapper`。跨表 JOIN 可以用 MyBatis-Plus 的 `@Select` 注解或在 XML 中写。

---

#### 问题 8：Dashboard 页面未使用 PageHeader 组件

**文件：** `Dashboard.vue`

**现状：** 其他 20+ 页面已经统一使用 `<PageHeader>`，但 Dashboard 仍然是旧式直接布局。视觉上最显眼的首页反而和子页面风格不一致。

**修复：** 在 Dashboard 顶部加一个 `<PageHeader title="运营看板" subtitle="今日概览" />`。

---

#### 问题 9：Navbar 顶部用户角色显示硬编码"管理员"

**文件：** `Sidebar.vue` 第 31 行


**问题：** 每个用户都显示「管理员」，不符合 RBAC 的多角色设计。

**修复：** 从 `authStore` 获取实际角色名显示。

### 🟢 P2 — 建议优化（体验/健壮性问题）

---

#### 问题 10：空状态/加载失败处理不统一

**涉及文件：** 几乎所有列表页

**现状：**
- `InventoryOut.vue` / `InventoryIn.vue`：错误时 `ElMessage.error`，但没有空数据占位
- `Materials.vue`：同上
- `Payment.vue`：表格没有 `empty` slot

**建议：** 全局 `<el-table>` 增加 `<template #empty><el-empty description="暂无数据" /></template>`

---

#### 问题 11：`InventoryOut` 出库表单中「用途」字段被 `purpose` 字段占据但实际不写入用途

**文件：** `InventoryOut.vue` 第 82-83 行

```html
<el-form-item label="用途" prop="purpose">
  <el-input v-model="form.purpose" type="textarea" :rows="2" />
</el-form-item>
```

这个字段在表格型表单（entry-table）之外，但 `purpose` 不在表格列中显示。实际上 entry-table 的「部门」列也只是自由文本——可以合并为「部门/用途」一列。

**建议：** 将 purpose 移到 entry-table 内，简化表单结构。

---

#### 问题 12：入库 `syncExpense` 时没有自动关联拨款批次的已使用金额

**文件：** `InventoryInService.java` 第 100-122 行

**现状：** 入库时如果选了 `allocationId`（拨款批次），只是存了关联字段，但没有更新该拨款批次的「已使用金额」。`BudgetService` 有 `getCurrentBudget` 也没有在入库时自动调用 `updateUsedAmount`。

**后果：** `WarehouseDashboardController.fundSummary` 中的 `remainingBalance` 需要用 `allocation - purchased` 自行计算，而不是从数据库中直接读。而且没有跨月度追踪。

**建议：** 在 `InventoryInService.create()` 中增加一步：如果 `allocationId != null`，调用 `BudgetService` 更新对应预算的 `used_amount`。

---

#### 问题 13：`StatsCardGroup` 的响应式列宽对 5 个卡片场景不够友好

**文件：** `StatsCardGroup.vue` 第 3 行

```html
<el-col :xs="12" :sm="12" :md="6" :lg="6">
```

**问题：** `:md="6"` 意味着每行最多 4 列（24/6 = 4）。如果传 5 个 items（如 Dashboard），第 5 个会折行独占一整行，非常难看。

**建议：** 增加一个 `cols` prop，允许父组件指定列数，例如 `cols="5"` 则 `:span="Math.floor(24 / cols)"`。
