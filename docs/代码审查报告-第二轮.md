### 🔴 P0 — 数据完整性

---

### 🟡 P1 — 功能完整性

#### 问题 B：手动支出登记无法标注 supplyCategory

**涉及文件：**
- `ExpenseCreateRequest.java` — 缺 `supplyCategory` 字段
- `ExpenseRecordService.create()` 行 73-87 — 未设置 `record.setSupplyCategory()`
- `Payment.vue` 行 610-618 (`submitExpense`) — 未传 `supplyCategory`
- `ExpenseController.java` — 无 PUT 端点

**场景：** 用户在「收支管理 → 支出管理」中手动登记一笔支出（如水电网费），无法标记这笔钱属于"社会化"还是"集中供养"。而通过入库同步生成的支出记录却正确标记了——造成同一张表里数据标签不统一。

**修复三步走：**
1. `ExpenseCreateRequest` 增加 `private String supplyCategory;`
2. `ExpenseRecordService.create()` 中加 `record.setSupplyCategory(request.getSupplyCategory());`
3. `Payment.vue` 支出表单增加 supplyCategory 下拉，`submitExpense()` 传参

---

#### 问题 C：ExpenseController 缺少 PUT/更新端点

**现状：** `ExpenseController` 只有 `GET`、`POST`、`DELETE`，没有 `PUT`。用户录错支出后无法修改。

**建议：** 参照 `InventoryInService.update()` 的模式增加一个 `update()` 方法。

---

### 🟢 P2 — 代码质量/一致性

#### 问题 D：多个 Service 存在完全相同的 `loadMaterialNames` / `loadElderlyNames` 方法

**涉及文件（至少 5 处）：**
- `InventoryInService.java` 行 142-151
- `InventoryOutService.java` 行 102-111
- `InventoryCheckService.java` 行 96-105
- `PaymentService.java` 行 229-241
- `DispenseService.java` 行 156 附近
- `FeeBillService.java` 行 512 附近
- `ElderlyService.java` 多处

所有方法几乎一模一样：拼接 `IN (?, ?, ?)` SQL → `jdbcTemplate.query()`。唯一区别是表名和列名。

**建议：** 抽取一个工具类 `BatchNameLoader`，用泛型或 lambda 封装。不是紧急问题，但减少 100+ 行重复代码。

---

#### 问题 E：部分 JDBC 查询有潜在 SQL 注入风险（低风险）

**涉及：**
- `PaymentService.java` 行 43-46：`"name LIKE ?"` 有参数化 ✅ 安全
- `FeeBillService.java` 行 470-481：JSON 路径拼接用 `+` 但来自常量 ✅ 安全
- `HomeServiceOrderService.java` 行 124：`"SELECT id, " + nameCol + " AS n FROM " + table` — **`nameCol` 和 `table` 来自变量，虽然当前上下文固定，但如果未来从外部传入有风险**

**建议：** `HomeServiceOrderService` 中如果 `nameCol`/`table` 是外部可控的，改为白名单校验。当前代码上下文下暂不紧急。

---

#### 问题 F：`ExpenseRecordService.list()` 缺少 supplyCategory 筛选参数
