# 用药管理升级需求文档

> 版本：v1.0 | 日期：2026-06-29  
> 项目：e-Hfnew 智慧养老管理系统  
> 关联模块：药物管理、老人档案、护工管理

---

## 一、背景与目标

### 1.1 现状评估

| 现有能力 | 说明 |
|----------|------|
| 药品档案 (t_drug) | 药品主数据：名称、通用名、规格、剂型、厂家、处方药标识 |
| 药品批次 (t_drug_batch) | 批次入库/剩余量/有效期追踪 + 近效期预警 |
| 发药单 (t_dispense_order) | 按老人创建发药单 → 确认发药 → 扣减批次库存 |
| 发药记录 (t_dispense_record) | 药品ID、数量、剂量、发药时间、执行护工 |

### 1.2 核心差距

**现有模型是"药房出库"视角——关注批次流向和库存扣减。养老机构实际需要的是"用药执行记录"视角——关注每位老人每天每顿吃了什么药。**

以下是养老行业标准的用药记录格式：

```
┌──────────┬──────────┬──────┬──────┬──────┬──────┬──────┬──────────┐
│   日期   │ 药物名称 │ 用量 │ 早晨 │ 中午 │ 晚上 │ 睡前 │   备注   │
├──────────┼──────────┼──────┼──────┼──────┼──────┼──────┼──────────┤
│ 06-26    │ 硝苯地平 │ 30mg │  ✓   │      │  ✓   │      │ 餐前服用 │
│ 06-26    │ 阿司匹林 │100mg │  ✓   │      │      │      │ 早餐后   │
│ 06-27    │ 硝苯地平 │ 30mg │  ✓   │      │  ✓   │      │          │
└──────────┴──────────┴──────┴──────┴──────┴──────┴──────┴──────────┘
```

**当前系统完全无法表达上述信息：**
- `DispenseOrder` 只有按天的发药单，没有「早晨/中午/晚上/睡前」这 4 个服药时段
- `DispenseRecord` 只有一条记录，无法表达「同一药品每日两顿」的执行状态
- 没有周期性的用药计划（如"硝苯地平每日早晚各一次，连续 30 天"）
- 老人档案详情页完全没有用药相关展示
- 没有用药执行确认（护工是否按时给老人喂药了？）

## 二、核心需求：用药执行记录表（Medication Administration Record, MAR）

### 2.1 数据模型

#### 新增表：`t_medication_plan`（用药计划）

```sql
CREATE TABLE t_medication_plan (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    elderly_id BIGINT NOT NULL COMMENT '老人ID',
    drug_id BIGINT NOT NULL COMMENT '药品ID',
    drug_name VARCHAR(100) NOT NULL COMMENT '药品名称（冗余，方便查询）',
    dosage VARCHAR(50) NOT NULL COMMENT '用量，如"30mg"、"1片"、"10ml"',
    dosage_unit VARCHAR(20) COMMENT '单位：mg/片/ml/粒',
    frequency_type VARCHAR(20) NOT NULL 
        COMMENT 'MULTI_DAILY每日/N_DAYS每N日/PRN必要时/ONCE一次性',
    interval_days INT DEFAULT 1 COMMENT '间隔天数（每N日服用一次时使用）',
    time_slots VARCHAR(50) NOT NULL 
        COMMENT '服药时段JSON: ["MORNING","AFTERNOON","EVENING","BEDTIME"]',
    start_date DATE NOT NULL COMMENT '开始日期',
    end_date DATE COMMENT '结束日期（null=长期）',
    total_quantity DECIMAL(10,2) COMMENT '发药总量（如：120片、500ml），用于自动推算耗尽日期',
    dosage_per_time VARCHAR(50) COMMENT '每次用量数值（如"1"、"10"、"30"）',
    times_per_day INT DEFAULT 1 COMMENT '每天服用次数（= time_slots 的长度）',
    depletion_date DATE COMMENT '预计耗尽日期（自动计算：start_date + total_quantity ÷ (dosage_per_time × times_per_day) 天）',
    instructions VARCHAR(500) COMMENT '服药说明：如"餐前服用"、"整片吞服不可嚼碎"',
    prescriber_name VARCHAR(50) COMMENT '处方医生',
    status VARCHAR(20) DEFAULT 'ACTIVE' COMMENT 'ACTIVE/PAUSED/COMPLETED/STOPPED',
    operator_id BIGINT,
    remark VARCHAR(200),
    deleted TINYINT DEFAULT 0,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_elderly (elderly_id),
    INDEX idx_date_range (start_date, end_date)
) COMMENT '老人用药计划';
```

#### 新增表：`t_medication_record`（用药执行记录 — 核心表）

```sql
CREATE TABLE t_medication_record (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    plan_id BIGINT COMMENT '关联用药计划ID',
    elderly_id BIGINT NOT NULL COMMENT '老人ID',
    drug_id BIGINT NOT NULL COMMENT '药品ID',
    drug_name VARCHAR(100) NOT NULL COMMENT '药品名称（冗余）',
    dosage VARCHAR(50) NOT NULL COMMENT '用量',
    record_date DATE NOT NULL COMMENT '服药日期',
    time_slot VARCHAR(20) NOT NULL 
        COMMENT 'MORNING早晨/AFTERNOON中午/EVENING晚上/BEDTIME睡前',
    status VARCHAR(20) DEFAULT 'PENDING' 
        COMMENT 'PENDING待执行/DONE已服用/SKIPPED跳过(医嘱)/MISSED漏服/REFUSED拒服',
    executor_id BIGINT COMMENT '执行护工ID',
    executor_name VARCHAR(50) COMMENT '执行护工姓名',
    executed_at DATETIME COMMENT '实际执行时间',
    skip_reason VARCHAR(200) COMMENT '跳过/漏服/拒服原因',
    remark VARCHAR(200),
    deleted TINYINT DEFAULT 0,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_elderly_date (elderly_id, record_date),
    INDEX idx_date_slot (record_date, time_slot),
    INDEX idx_plan (plan_id)
) COMMENT '老人用药执行记录';
```

### 2.2 核心业务流程（自动化三阶段）

**此流程是养老院从纸质管理升级为电子化的关键创新——工作人员一次性录入,系统自动完成所有后续工作。**

```
┌──────────────────────────────────────────────────────────────┐
│  录入阶段（工作人员一次性操作）                               │
│                                                              │
│  工作人员打开「新增用药」表单，填写：                         │
│    老人: 张大爷              药品: 硝苯地平缓释片            │
│    发药总量: 120 片          每次用量: 1 片                  │
│    服药时段: ☑早晨 ☑晚上     每天次数: 2 次（自动计算）     │
│    开始日期: 2026-06-01                                      │
│                                                              │
│  系统自动计算：                                              │
│    耗尽日期 = 06-01 + (120 ÷ (1×2)) = 06-01 + 60天         │
│           = 2026-07-31                                      │
│                                                              │
│  [点击保存]                                                  │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│  回填阶段（系统自动）                                        │
│                                                              │
│  从 2026-06-01 到今天 2026-06-29，共 29 天                 │
│  每天 2 条记录（早晨 + 晚上），共生成 29×2 = 58 条记录      │
│                                                              │
│  系统写入 t_medication_record：                             │
│    06-01|MORNING|PENDING   06-01|EVENING|PENDING            │
│    06-02|MORNING|PENDING   06-02|EVENING|PENDING            │
│    ...                                                       │
│    06-29|MORNING|PENDING   06-29|EVENING|PENDING            │
│                                                              │
│  过往日期自动标记为 DONE（药物已消耗），当日标记为 PENDING   │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│  持续阶段（每日凌晨自动）                                    │
│                                                              │
│  Quartz 定时任务 @daily 00:01：                              │
│  1. 扫描所有 status=ACTIVE 的用药计划                        │
│  2. 若 plan.depletion_date >= 今天：生成今天的用药记录       │
│  3. 若 plan.depletion_date == 昨天：                        │
│     - 生成最后一天记录                                       │
│     - 将 status 改为 COMPLETED（药物耗尽）                  │
│     - 触发 Dashboard 预警：「张大爷 硝苯地平 已用完」        │
│                                                              │
│  同时 @daily 23:00：                                         │
│  将所有当天仍为 PENDING 的记录标记为 MISSED                  │
└──────────────────────────────────────────────────────────────┘
```

### 2.3 数据流全景

```
                    ┌─────────────────┐
                    │  t_drug         │  ← 药品主数据
                    │  (name, spec)   │
                    └────────┬────────┘
                             │ drug_id
                    ┌────────▼────────┐
  一次性录入         │ t_medication_plan│  ← 总量120片、每次1片、每日2次
  自动计算耗尽日期    │ total_quantity    │    自动推算 depletion_date=07-31
  自动回填历史记录    │ depletion_date   │    start_date → today 全部生成
                    └────────┬────────┘
                             │ plan_id
                    ┌────────▼────────┐
  每日凌晨自动生成    │t_medication_record│ ← 每天早晨一条、晚上一条
  23:00自动标记漏服   │ (date, time_slot) │    护工看板逐条确认执行
                    └────────┬────────┘
                             │ 护工确认/跳过/拒服
                    ┌────────▼────────┐
  看板实时更新       │ status → DONE   │
  药物耗尽自动预警    │ executor_id     │
                    └─────────────────┘
```

## 四、后端 API 设计

### 4.1 用药计划 CRUD

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/medication/plans` | 分页列表（可按 elderlyId/drugId/status 筛选） |
| POST | `/api/medication/plans` | 创建用药计划（自动生成今日起执行记录） |
| PUT | `/api/medication/plans/{id}` | 编辑用药计划 |
| PUT | `/api/medication/plans/{id}/pause` | 暂停 |
| PUT | `/api/medication/plans/{id}/resume` | 恢复 |
| PUT | `/api/medication/plans/{id}/stop` | 停止（不再生成新记录） |
| DELETE | `/api/medication/plans/{id}` | 删除（逻辑删除） |

### 4.2 用药执行记录

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/medication/records` | 分页列表（按 elderlyId/date/timeSlot/status 筛选） |
| GET | `/api/medication/records/today` | 今日所有老人用药状态（看板核心接口） |
| PUT | `/api/medication/records/{id}/confirm` | 确认服药（传 executorId） |
| PUT | `/api/medication/records/{id}/skip` | 跳过（传 skipReason） |
| PUT | `/api/medication/records/{id}/refuse` | 拒服（传 skipReason） |
| PUT | `/api/medication/records/confirm-batch` | 批量确认（传 recordIds + executorId） |
| GET | `/api/medication/records/elderly/{elderlyId}` | 某老人近 N 天用药记录（老人详情页用） |

### 4.3 定时任务

| 任务 | 触发时间 | 说明 |
|------|---------|------|
| `generateDailyRecords` | 每日 00:01 | 扫描所有 ACTIVE 计划，为当天生成执行记录；若耗尽日期已到则自动将计划标记为 COMPLETED |
| `checkMissedRecords` | 每日 23:00 | 将当天仍为 PENDING 的记录标记为 MISSED（漏服） |
| `checkDepletionWarnings` | 每日 08:00 | 扫描 depletion_date ≤ 7 天内的计划，推送药物耗尽预警到 Dashboard |
| `syncLeaveStatus` | 每日 00:05 | 检测今天刚返院的老人 → 自动恢复其用药计划 + 顺延 depletion_date |

### 4.4 老人请假/退住联动（关键边界场景）

**此节处理养老院最核心的两个特殊情况——老人请假和退住时，用药系统如何自动响应。**

#### 场景一：老人请假（ON_LEAVE）

```
时间线：
  06-25  张大爷正常服药
  06-26  张大爷请假外出 3 天（t_elderly_leave: start=06-26, end=06-28）
  06-29  张大爷返院（t_elderly_leave.status → RETURNED）

系统行为：
  06-26 00:01  定时任务检查到 elderly.status=ON_LEAVE → 跳过生成用药记录
  06-27 00:01  同上
  06-28 00:01  同上
  06-29       elderly.status 恢复 ACTIVE → 恢复生成记录
              同时 plan.depletion_date 自动顺延 3 天（药物未被消耗）
```

**实现逻辑：**

```java
// MedicationService.generateDailyRecords(LocalDate date)
for (MedicationPlan plan : activePlans) {
    // ★ 关键检查：老人今天是否请假中？
    if (isElderlyOnLeaveToday(plan.getElderlyId(), date)) {
        continue;  // 请假期间不生成用药记录，不扣减天数
    }
    // ★ 关键检查：老人是否已退住？
    if (isElderlyDischarged(plan.getElderlyId())) {
        plan.setStatus("STOPPED");
        plan.setRemark((plan.getRemark() == null ? "" : plan.getRemark()) + "；退住自动停止");
        medicationPlanMapper.updateById(plan);
        continue;
    }
    // 正常生成
    for (String slot : plan.getTimeSlotsAsList()) { ... }
}
```

#### 场景二：老人退住（DISCHARGED）

```
07-15  张大爷正常服药
07-16  张大爷办理退住（elderly.status → DISCHARGED）

系统行为：
  07-17 00:01  定时任务检测到 DISCHARGED
               → 所有该老人 ACTIVE 计划 自动 → STOPPED
               → 不再生成新记录，不删除历史记录
               → 已生成的 PENDING 记录保留（不标记 MISSED，因为不是护工漏服）

可选联动（仓库模块）：
  - 退住时统计剩余药物，生成「退住药物退回清单」
```

#### 状态转换矩阵

```
elderly.status        每日定时任务行为
──────────────────────────────────────────────
ACTIVE (在住)         → 正常生成记录，正常扣减天数
ON_LEAVE (请假中)     → 跳过生成，不扣天数，depletion_date 自动顺延
DISCHARGED (退住)     → 计划自动 STOP，不退还原有记录
```

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/medication/plans/{id}/pause-by-leave` | 请假时调用：暂停 + 标记请假开始日 |
| POST | `/api/medication/plans/{id}/resume-from-leave` | 返院时调用：恢复 + depletion_date 顺延请假天数 |

### 4.5 自动耗尽日期计算（核心业务逻辑）

**公式：**

```
depletion_date = start_date + ⌊ total_quantity ÷ (dosage_per_time × times_per_day) ⌋ - 1

示例：
  发药总量 120 片，每次 1 片，每天 2 次，开始日期 06-01
  每天消耗 = 1 × 2 = 2 片
  可服用天数 = 120 ÷ 2 = 60 天
  耗尽日期 = 06-01 + 60 - 1 = 07-30
```

**代码逻辑（伪代码）：**

```java
// MedicationService.createPlan()
BigDecimal dailyDosage = dosagePerTime.multiply(BigDecimal.valueOf(timesPerDay));
long days = totalQuantity.divide(dailyDosage, 0, RoundingMode.FLOOR).longValue();
LocalDate depletionDate = startDate.plusDays(days - 1);
plan.setDepletionDate(depletionDate);

// If end_date wasn't manually set, use depletion_date
if (plan.getEndDate() == null) {
    plan.setEndDate(depletionDate);
}
```

### 4.5 回填历史记录逻辑

**触发时机：** 创建用药计划时，若 `start_date < 今天`，自动回填。

```java
// MedicationService.backfillRecords(MedicationPlan plan)
LocalDate today = LocalDate.now();
LocalDate cursor = plan.getStartDate();
while (!cursor.isAfter(today)) {
    for (String slot : plan.getTimeSlotsAsList()) {
        MedicationRecord record = new MedicationRecord();
        record.setPlanId(plan.getId());
        record.setElderlyId(plan.getElderlyId());
        record.setDrugId(plan.getDrugId());
        record.setDrugName(plan.getDrugName());
        record.setDosage(plan.getDosage());
        record.setRecordDate(cursor);
        record.setTimeSlot(slot);
        // 过去的日期自动标记为已服用（纸质记录视为已完成）
        record.setStatus(cursor.isBefore(today) ? "DONE" : "PENDING");
        medicationRecordMapper.insert(record);
    }
    cursor = cursor.plusDays(1);
}
```
